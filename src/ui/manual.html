ApkStart West User Manual and Troubleshooting Guide

Version: v0.6.4 · Platform: Windows 10/11 x64 · Updated: 2026-11-22 ApkStart West is an Android app runner for Windows: it lets Android apps install, show up on your desktop and open with a double-click, like native Windows software. This manual first shows you how to use it, then gives step-by-step solutions organized by symptom. Every step matches a button or menu that really exists in the app.

1. ApkStart West in 30 seconds

Desktop icon (the app's real icon, a .lnk shortcut)
      │ double-click
      ▼
ApkStart.exe --launch <package name>
      │ Android runtime not running? → starts it automatically (Android 14 emulator, bundled or downloaded on first start)
      ▼
Opens the app through the launch entry resolved by the system (not the main Activity hard-coded in the APK)
      ▼
Emulator window = app window (custom title, icon, portrait ratio, full-screen centered)

What makes it different

  • 🖱️ Double-click an .apk to install it: after you register the file association, double-clicking an APK parses it, installs it and creates a desktop icon.
  • 🧩 One desktop icon per app: the icon is extracted offline from inside the APK, and double-clicking it opens the app directly.
  • 🪟 The app is just a window: natively rendered, full-screen fills the screen height and is centered, windowed mode can be dragged and resized, and each app remembers its own size.
  • 🔍 Searchable from Windows: two shortcuts, one on the desktop and one in the Start menu (Programs\ApkStart West\).
  • 📁 Shared data: %USERPROFILE%\ApkStartShared ↔ /sdcard/ApkStartShared inside Android, synced both ways.
  • 🪶 Its own runtime: it does not depend on any emulator installed on your PC (BlueStacks, WSA and so on).
Note: this project is an early version, maintained in spare time, open source, free and ad-free. Running into problems is normal, and this manual exists for that.

2. Installation and first start

2.1 Choose your edition

Download from:

  • GitHub: github.com/mvoloch/apkstart-west/releases
EditionFile nameWhen to choose it
Full portable editionApkStart-v*-win64-full.zip (about 830 MB, ~1.3 GB unpacked)You do not want to install or wait for downloads: unzip and use, the whole runtime is in the package
Installer editionApkStart-v*-Setup.exe (about 1.3 GB)You want desktop / Start menu shortcuts and an uninstall entry
Light portable editionApkStart-v*-win64-portable.zip (96 MiB, ~227 MB unpacked)You just want to try it first: the runtime is downloaded on first start
⚠️ Always use the latest version (currently 0.6.4). Older versions (0.5.x and earlier) either had no bundled runtime and looked for or downloaded a 1.5 GB runtime on every start, or used an embedded window by default. That is the typical source of "very slow, will not open, a window with a rotate button shows up". If you upgraded from an old version, make sure the desktop icons point to the new program folder.

2.2 What happens on first start

  1. (Light edition only) Download the runtime: adb, the Android Emulator and the Android 14 system image, downloaded in 8 parallel chunks with resume support. The full edition skips this step.
  2. Unpack the image the first time: the xz image is unpacked to %APPDATA%\apkstart-west\system-images (about 20 seconds, done only once).
  3. Build /data the first time: ApkStart West generates the ext4 user data itself, with encryption and SELinux labels (the official image only ships a 1 MB placeholder).
  4. Automatic boot: after that, opening an app is just one am start. A cold start takes about 23 seconds, and a snapshot hit about 10 seconds.
A slow first start is normal: it is a "one-time cost". After that, apps open in seconds.

3. Everyday use

3.1 Installing apps

Pick any of three ways:

  • Double-click an APK file (register the association first: Settings → Integration and files → Associate .apk files);
  • Choose "Install app" in the main window;
  • Command line: ApkStart.exe <path\to.apk>.

Split packages .apks / .xapk are supported (install-multiple is used automatically). After installing, desktop and Start menu shortcuts are created automatically.

3.2 Opening apps

Just double-click the desktop icon. All apps share one runtime, so the second app starts almost instantly.

3.7 Online updates

Settings → Updates and about → Check for updates, or tray menu (right-click) → Check for updates. Updates come from GitHub Releases and are downloaded in parallel chunks. Updating does not remove your runtime, installed apps or snapshots.

The portable edition supports incremental updates: every release also publishes a "code manifest" and a small package that holds only the program code (a few MB, while the whole package is about 100 MB). If your Electron shell version has not changed, the update downloads only this small package, verifies it file by file and replaces the program code, which takes a few seconds. If the shell version changed, the manifest is missing or any check fails, it automatically falls back to downloading the full package, so an update cannot break the program.

Note: incremental updates apply to users who installed the portable edition through "Check for updates". They do not affect installed apps, Android data, the runtime or snapshots.

4. Three core concepts (the key to understanding errors)

Most "strange problems" come down to one of the three things below. Spend one minute on them and troubleshooting gets much easier.

4.1 Runtime / system image

ApkStart West does not emulate an "empty Android". It loads a complete Android 14 system image as its base. Since 0.6.3 there is only one generic image (Google Play x86_64) and both x86 and ARM apps run on it. The old split into an "AOSP image / compatibility image" is gone.

  • Missing / corrupt image, or an image incompatible with old user data → boot failure, stuck at boot, repeated restarts.
  • User data (/data) is a thin difference layer, and the system image is shared once for the whole PC.

4.2 Hardware acceleration

For the emulator to run fast it needs CPU virtualization acceleration. On Windows there are only two ways:

MethodWhat it isWho needs admin rightsRestart needed after?
WHPXThe Windows feature "Windows Hypervisor Platform" (HypervisorPlatform)When you turn the feature onYes
AEHDGoogle's own kernel driverWhen you install the driverNo

It also runs without acceleration (pure software emulation, TCG), but boot takes minutes and the picture drops frames. That is "slow", not "failed to start". ApkStart West falls back automatically and retries with up to 4 sets of parameters, in the order "rendering backend → acceleration method → memory / cold start".

Do not treat VirtualMachinePlatform (used by WSL2) as the acceleration switch. The emulator needs HypervisorPlatform. If you only turn on the former, emulator -accel-check still says it is unavailable.

4.3 ARM translation layer

Many Android apps ship only native ARM libraries (arm64-v8a / armeabi-v7a), while the system image is x86_64. A "translation layer" is needed to hand ARM instructions to the x86 CPU. The generic image in 0.6.3 includes a recent ndk_translation layer, so installing ARM apps usually needs no setup.

  • The first time an ARM app is met, if the translation layer component is not in place yet, ApkStart West automatically completes the compatibility image and restarts the runtime to retry (see 6.3).
  • Old images (API 30) have compatibility problems with the new translation layer (for example some apps trigger DoBadTrampoline SIGABRT). The Android 14 image fixes this.

5. When something goes wrong, start here: PC check-up and automatic checks

Before you read through this manual, let the app check itself first. It can fix most problems automatically.

5.1 PC check-up · automatic setup

Where: Settings → Diagnostics and repair → Start check

  • What it checks: whether CPU virtualization (VT-x/SVM) is on, whether Hyper-V / the hypervisor platform is available, graphics card / video memory / driver, memory, Windows version, emulator -accel-check, the AEHD driver.
  • Click "Apply recommended settings" to write the safe items automatically: memory / core count / render resolution / picture quality / force software emulation when there is no acceleration. They are saved as a driver for this PC and applied automatically from then on.
  • Result levels: ok (normal) / warn (works but could be better) / bad (will not run unless fixed). Each line has a color and an explanation.

Only two kinds of things need you to act yourself:

  • BIOS virtualization: restart into the BIOS → turn on Intel VT-x / AMD SVM → Enabled (the app cannot do this for you).
  • Windows feature / acceleration driver: see 6.1.

5.2 Automatic checks (auto-debug)

Where: Settings → Diagnostics and repair → "Automatic checks · smart diagnosis"

In the background it checks the PC every 10 minutes and lists problems in six categories. Each one can be handled with one click (restart the runtime, clear locks, clear orphan processes, discard the snapshot, clean the disk, reset Android networking and so on), and after the fix it checks again automatically:

CategoryProblems covered
RuntimeThe real reason of the last failed start, stuck boot, leftover lock files, orphan emulator processes, empty snapshot shell, no hardware acceleration
Device connectionadb unauthorized, offline, runtime running but adb sees no device
StorageFree disk space, data partition setting differs from reality, shared folder not writable
SettingsScreen orientation conflicts with the physical panel, auto full screen not working in a separate window
Network / logsNo network on the Android side, download source unreachable, errors in recent logs
Two principles: a failed probe is never treated as a problem (if the state cannot be read it says "unknown" and never guesses), and the same old problem does not nag you again and again.

5.3 Export a diagnostic report

Where: Settings → Diagnostics and repair → Export diagnostic report (or the button of the same name on the Integration and files page)

The report is plain text. It holds the PC configuration, the launch parameters that were selected automatically, the logs and the diagnostic conclusions. Attach it when you report a problem and it helps a lot to find the cause quickly.

5.4 Built-in manual and automatic tutorials

Since 0.6.3 this manual is built into the app: the "?" button in the title bar of the main window and "Open user manual" under Settings → Updates and about both open it directly. You can search it, scroll it and print / save it as PDF. When it opens, it jumps to the chapter related to the current problem.

Automatic checks and repairs also bring the tutorial to you:

  • When an automatic check finds a problem, the item has a "Tutorial" button on the right that opens the matching chapter;
  • For hardware acceleration, install failures, the ARM translation layer, adb authorization, no sound and similar problems, when the automatic fix fails the matching tutorial opens by itself, so you do not need to come and look it up here;
  • The same tutorial opens automatically only once per run, so it will not keep interrupting you.
To open it manually: the ? button in the title bar. To stop the automatic pop-up for now, turn off notifications in the automatic checks settings. You can still open the tutorial from the "Tutorial" button of any problem item.

6. Solutions to common problems

6.1 "Hardware acceleration is off" / slow boot

Symptom: Settings / diagnostics say "no hardware acceleration at the moment" or "hardware acceleration unavailable"; boot takes minutes and the picture drops frames.

First, be clear: this is usually "slow", not "will not open". ApkStart West has already fallen back to software emulation. You only need acceleration if you want smooth performance.

What to do:

  • Settings → Diagnostics and repair → PC check-up → find "Hardware acceleration is off" → click Fix. A UAC prompt appears once and WHPX is turned on automatically. If it cannot be turned on (the system does not support it, or you answered no), the AEHD driver is installed instead.
  • To do it by hand, open the "Turn Windows features on or off" dialog:

1. Tick "Windows Hypervisor Platform" (HypervisorPlatform); 2. click OK and restart the PC once.

You can also run this in an administrator PowerShell:

dism /online /enable-feature /featurename:HypervisorPlatform /all /norestart
dism /online /enable-feature /featurename:VirtualMachinePlatform /all /norestart
Two pitfalls: ① do not turn on only VirtualMachinePlatform, that is not the acceleration the emulator needs; ② if VT-x/SVM is not on in the BIOS, go into the BIOS first as described in 5.1, otherwise the Windows feature does nothing even when it is on. If your graphics driver is more than 3 years old, update it from the manufacturer's website; ApkStart West never installs drivers automatically (a wrong driver is worse). Some old graphics cards / integrated GPUs need a compatibility patch, see Settings → Diagnostics and repair → Drivers · compatibility patches.

6.2 Install failed (INSTALL_FAILED_*)

Symptom: an error appears when installing an app. The message usually starts with "Install failed" and ends with an INSTALL_* error code.

ApkStart West explains the raw English error in plain language. Use the table below:

6.3 System image has no ARM translation layer / ARM apps will not install or crash

Symptom: installing reports INSTALL_FAILED_NO_MATCHING_ABIS and the message says the app only has native ARM libraries and the current system image has no ARM translation layer; or the app installs but crashes right at launch, and the log shows DoBadTrampoline, libndk_translation, UnsatisfiedLinkError or ...so not found.

Why: 0.6.3 uses one generic Android 14 image for both x86 and ARM, and the translation layer is built in. Older versions needed you to switch images by hand. The "Generic compatibility image (managed automatically)" switch is now only kept for old configurations and normally needs no manual change.

What ApkStart West does automatically:

  1. If installing reports NO_MATCHING_ABIS, it switches to the compatibility image → restarts the runtime → pushes the installed apps back from their local APK backups → installs again (the log says it is switching to the compatibility image and restarting the runtime).
  2. If an app crashes at launch and the log clearly points to the ARM translation layer (such as DoBadTrampoline), it switches to the Android 14 compatibility image and retries (the log says an ARM translation layer crash was detected).

What you need to do:

  • Be patient: switching images restarts the runtime, which takes about 40 seconds to 1 minute, and you may see a notice window meanwhile.
  • Check the image is in place: Settings → Basics and install → Runtime, look at the status of "Generic compatibility image (managed automatically)". If it shows not downloaded, click "Download compatibility image" (about 1.5 GB), then restart the runtime for it to take effect.
  • Still crashing: a few apps have deeper anti-emulator checks (they force-check real sensors, the baseband and so on) and cannot run in an emulator. For these the app shows an explanation; it is a limitation, not a fault.

What if you see a red "Install failed" while the message says it is "switching to the compatibility image and will retry"?

This was a display bug in an older version: the image file was on disk, but it was reused with an old runtime that had no translation layer, so the switch-and-retry was skipped and the failure was reported directly, while the message still said "retrying". You are not on the latest code, please upgrade to the latest 0.6.4 build (the version this manual describes has fixed it: before installing it probes the real translation ability of the current runtime instead of only checking whether the image file exists; NO_MATCHING_ABIS always triggers switch + restart + clearing the old snapshot + reinstall; and if it fails a second time it tells you honestly instead of falsely claiming it is retrying). After upgrading, install again.

Tested: an app that ships only arm64-v8a libraries installs, opens and plays video normally on the Android 14 image with the new translation layer. The current runtime reports ro.product.cpu.abilist = x86_64,arm64-v8a, which means the translation layer is active.

6.4 adb unauthorized (allow USB debugging)

Symptom: diagnostics report "adb unauthorized" or "Android debugging authorization not completed", adb devices shows unauthorized, and the app never starts.

The right way (in order):

  1. Look for an emulator window showing the "Allow USB debugging?" dialog. Go to that window and click Allow, and tick "Always allow from this computer" so it never asks again.
  2. If the window cannot be clicked or never appears: Settings → Basics and install → Reset Android data / Clear Android data and try again (this removes installed apps; the APK files are kept and are reinstalled automatically, and the system itself is not affected).
⚠️ Never delete %USERPROFILE%\.android\adbkey. In practice that is the opposite of what you want: Android writes a new public key only when the adb_keys file does not exist. If you change to a new private key, the old public key stored in the system stays valid, the two do not match, and authorization will never succeed.

Command-line check: the adb server of ApkStart West runs on a dedicated port 5044 (completely separate from your own 5037):

$env:ANDROID_ADB_SERVER_PORT = 5044
adb devices    # you should see emulator-5554

Do not run adb connect by hand on port 5555: the Play image shows an "Allow USB debugging" prompt on top of the app, which looks like the program is broken.

6.5 Double-clicking the icon does nothing / endless spinner / window with a rotate button

Problems like this almost always point to the launch entry or window takeover. Check in the order below.

① Make sure you are using the new version

  • Open the log %APPDATA%\apkstart-west\logs\app.log and look at the beginning: start v0.6.4 is correct. If it shows v0.5.x, the desktop / Start menu icons point to an old folder.
  • The old version (0.5.x) has no bundled runtime and uses the embedded window by default → "very slow + a shell window with a rotate button". Switch to 0.6.4 and point the shortcuts to the new ApkStart.exe.

② Know how long boot takes

A cold start of about 23~48 seconds and a restart for an orientation change of about 50 seconds are normal. During that time the icon seems to "do nothing" but the runtime is booting in the background. Do not click several times: repeated clicks make a second instance take over the emulator, and the cleanup when the first instance exits may close the emulator as well, causing a failure (0.6.3 added owner.pid protection, but waiting in the queue can still look like nothing is happening). Click once and wait for it to come up.

③ The native window did not take over → falls back to the embedded window with a rotate button

If the log shows attach failed or emu:0, the window proxy did not find the emulator window and the program fell back to embedded mode (the shell window with a title bar and a rotate button that you see).

  • This is easy to trigger when launching from a directory junction or a non-standard path; 0.6.3 makes the proxy resolve the real path before matching. If it still happens, send the log with your feedback.

④ Reset Android data (last resort)

Settings → Basics and install → Reset Android data (asks for confirmation). It removes installed apps and data but keeps the system itself; the app list is kept and apps reinstall automatically when you open them. It helps with all kinds of "will not open" caused by a corrupt data partition or /data that cannot be mounted.

6.7 App has no sound / sound is very quiet

Symptom: videos and alert sounds in an Android app are completely silent; or other Windows programs have sound and only the apps in ApkStart West do not.

First tell them apart: if the system itself has no sound either, fix Windows audio first. Only follow the steps below if just the apps in ApkStart West are silent.

  1. Windows volume and output device: click the volume icon in the taskbar and make sure it is not muted, the volume is not 0, and the output device is the headset / speakers you are using. Open "Volume mixer" and check whether the ApkStart West / Android runtime row is muted on its own or set to 0.
  2. In-app volume: some apps set the media volume to 0 the first time they open. Turn it up in the app's own settings or with the Android volume keys. Some video apps may also have turned off autoplay sound inside the app.
  3. The ApkStart West sound switch: Settings → Performance and resources → Android sound must be ticked. Automatic checks look at this item; if it is off, it is reported under "Settings → Diagnostics and repair", and one click on "Fix" turns it on. After changing it you must restart the Android runtime once (only when both sound and microphone are off is it started with -no-audio, and a change made while running does not produce sound right away).
  4. Windows audio service: press Win+R, type services.msc, find Windows Audio and make sure the status is "Running" and the startup type is "Automatic". If it is disabled, right-click and start it. The 0.6.3 automatic checks also detect this and tell you. In an administrator PowerShell you can run net start Audiosrv.
  5. Bluetooth headset / several output devices: after switching to a Bluetooth headset, Windows sometimes does not move programs that are already running. Disconnect and reconnect the headset, or restart the Android runtime once.
  6. Still no sound: use "Settings → Diagnostics and repair → Export diagnostic report" and send it with your feedback. The report includes the sound switch and the audio service state, so it can show whether the cause is the configuration, a system service or the app itself.
When the automatic fix fails, the app opens this section by itself. If you turned off automatic check notifications, you can also get here from the "Tutorial" button of an automatic check item or from the ? in the title bar.

6.8 Failed to start: 0xC0000135 (DLL load failure)

Symptom: after you open an app it spins forever or exits right away, and the diagnostic report shows exit code 0xC0000135 (decimal 3221225781).

First, correct a common wrong guess: 0xC0000135 only means "a DLL failed to load". It does not always mean a missing VC++ runtime and it does not always mean antivirus deleted a file. There are two common causes behind the same exit code, so do not keep reinstalling for the first one only:

  1. A VC++ runtime is really missing: the Android runtime (Qt6 / qemu) depends on Microsoft VC++ 2015-2022 (x64). If Settings → Diagnostics and repair clearly reports "VC++ runtime (x64) missing", that is a measured missing dll file, and you can click "Fix" to install it in one click.
  2. Antivirus quarantined runtime files: if dll files in the runtime folder were quarantined / deleted, this code appears too. Add the ApkStart West install folder and the runtime data folder to the antivirus allow list, then install again.

Check in this order:

  1. See whether diagnostics really report a missing VC++: if Settings shows "VC++ runtime (x64) missing", click its one-click fix and restart the PC before trying again. Do not reinstall just because the exit code is 0xC0000135; first confirm that this item was really reported.
  2. VC++ is not reported but it still fails: quit ApkStart West completely (tray icon → Exit) and open it again; check the "Controlled folder access / ransomware protection" of your antivirus, allow ApkStart West and restart; if it still fails, run it from a plain-English folder (such as C:\ApkStart).
  3. Get the exact name of the failing DLL (advanced): when you report the problem, the most valuable thing is to tell the developers which dll is missing. In Event Viewer → Windows Logs → Application look for the Application Error of ApkStart / emulator and read the FaultingModuleName field; or use "Settings → Diagnostics and repair → Export diagnostic report" and send the report with your feedback.
  4. If adb crashes too: if the event log also shows adb.exe with 0xC0000409, that is a separate problem (device connection error) and not the direct cause of the emulator exit. Handle the startup first with steps 1–3 above and mention the adb problem separately in your feedback.
This section opens by itself: when a failed start / failed fix is judged to be a DLL problem, the app opens straight here. You can also open it any time from the "Tutorial" button of an automatic check item or from the ? in the title bar.

6.9 App cannot use the microphone / cannot record voice

Symptom: voice messages, calls, recording or voice scanning in an app do not work, with a message such as "no microphone / recording device unavailable".

  1. The ApkStart West microphone switch: Settings → Performance and resources → Microphone input must be ticked. It is on by default; if it was turned off, automatic checks report "Microphone input is turned off in Settings" under "Settings → Diagnostics and repair", and one click on "Fix" turns it on and restarts the runtime. After changing it you must restart the Android runtime once (the switch decides whether the emulator exposes a recording device to Android).
  2. Windows microphone permission: Settings → Privacy & security → Microphone, make sure both "Let apps access your microphone" and "Let desktop apps access your microphone" are on. Android runs inside a desktop app, and if this is off the system cannot give it the microphone.
  3. Check that Windows can record: record a clip with the built-in "Voice Recorder" and make sure the microphone and the input device (headset mic / webcam mic / separate mic) work and are not muted.
  4. Pick the right input device: if several microphones are plugged in, set the one you want as the default device in Windows "Sound settings → Input". The emulator uses the system default input device.
  5. How sound and microphone relate: the emulator turns the audio subsystem off completely to save CPU only when both "Android sound" and "Microphone input" are off; as long as one is on, the other works normally.
When the microphone is off, the app only fails to find a recording device and shows no obvious error. Automatic checks report this to you proactively; you can also open this section by hand from the ? in the title bar.

6.10 Dedicated / integrated GPU (graphics preference)

Symptom: the PC has a dedicated graphics card but the app picture stutters or drops frames; or a laptop gets hot and drains the battery and you want to use the integrated GPU to save power.

The Android picture of ApkStart West uses -gpu host hardware rendering, which really uses your graphics card. Since 0.6.4 all graphics cards (NVIDIA / AMD / Intel) prefer host by default, and AMD/Intel are no longer dropped to software rendering as in older versions, which meant giving up the graphics card on purpose. If host crashes on this PC, it automatically falls back to a software backend and you can keep using the app.

Choose which graphics card to use: when the PC has both a dedicated and an integrated GPU, Windows sometimes assigns the emulator to the integrated one. Settings → Performance and resources → Graphics preference lets you choose explicitly:

OptionGood for
System default (recommended)Let Windows choose by power / load, the easiest choice on most PCs
Prefer dedicated GPUGames, video, and anything needing a high frame rate; uses more power and runs hotter
Prefer integrated GPULight apps, idling, saving laptop power; somewhat slower
  • This works through the Windows "Graphics performance preference" (UserGpuPreferences) for the emulator process and is only effective on Windows 10 1803 and later; older systems ignore it automatically and startup is not affected.
  • It takes effect the next time the Android runtime starts; the settings page shows whether it is already in effect.
  • On old AMD drivers host sometimes crashes: update the graphics driver; if that is not enough, under "Settings → Diagnostics and repair → Drivers · compatibility patches" turn on the bundled AMD integrated GPU swangle sample patch, which pins rendering to a more stable backend.

9. Getting help and giving feedback

When you report a problem, please attach these three things. They greatly speed up finding the cause:

  1. Diagnostic report: Settings → Diagnostics and repair → Export diagnostic report;
  2. The last 20 lines of app.log: %APPDATA%\apkstart-west\logs\app.log;
  3. Your version and edition: for example "installer edition 0.6.4" or "full portable edition 0.6.4".
