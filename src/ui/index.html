Install Android to the virtual disk

The virtual machine window is open. Follow the 6 steps below once; after that ApkStart West starts straight from the disk and no longer needs the image.

  1. Boot menu: use ↓ to select Installation - Install Android-x86 to harddisk, then press Enter
  2. Choose Partition: choose Create/Modify partitions; when asked whether to use GPT, choose No
  3. cfdisk partitioning: New → Primary → press Enter for the default size → Bootable → Write → type yes → Quit
  4. Format: choose vda1 → when asked to format, choose ext4 → Yes
  5. Bootloader and system: for Install GRUB choose Yes; for Install /system as read-write choose Yes
  6. Finish: when progress reaches 100%, click “I have finished installing” below (ApkStart West restarts automatically and takes over)

If adb is later reported as not connected: in the virtual machine window press Ctrl+Alt+F1 to open a terminal and run setprop service.adb.tcp.port 5555, stop adbd, start adbd, then press Ctrl+Alt+F7 to go back to the graphical screen.

Detecting…
Memory, CPU cores, rendering backend, ports and acceleration are all chosen automatically; if startup fails it retries with safer settings, so you do not need to change anything. ApkStart West uses a dedicated adb server port (5044) (your own adb uses 5037), so in a terminal adb devices does not show this Android device — this is on purpose, to keep them separate. To connect, set $env:ANDROID_ADB_SERVER_PORT=5044 and then run adb. Note: do not run adb connect by hand on port 5555, because that makes an “Allow USB debugging?” system dialog pop up over the running app.
Calculating…
The system image is shared by the whole PC, and app data is stored in a differencing layer; old images, old snapshots, logs and lock files can all be reclaimed. Logs roll over automatically when they reach the limit, so they never grow without bound. “Reset Android data” really deletes several GB of user data and keeps only the system itself.
The diagnostic report is for troubleshooting; rebuilding restores the Desktop and Start menu entries

App window
Press F11 or right-click the tray icon at any time to switch; full screen only enlarges the window and does not change the picture ratio, and switching does not restart the app.
When on, every app fills the screen as soon as you open it, so you no longer need to press F11. It works best together with “Landscape” below — the landscape panel already matches the screen ratio, so full screen has no black bars.
Whether Android shows landscape or portrait is decided by the real orientation of the virtual phone panel. When the panel orientation does not match the orientation the app declares, Android only gives the app a narrow strip in the middle and pads the sides with black, and resizing the window or changing the resolution cannot fill it. “Follow the app” reads the app’s orientation when you install the APK and switches the panel to the matching one at startup, so apps such as Hongguo and Modu appear upright and fill the screen. The runtime restarts once (about ten-odd seconds) only when the orientation is wrong; after that, apps with the same orientation open instantly.
In Android, the auto-rotate switch is on by default. Note that this does not affect the picture orientation: the panel and screen orientation are still decided by the policy above plus ignoring the app’s orientation requests, so a sensor cannot tilt it. It only matters for the few apps that read this switch value.
A width of 720 at 190 dpi equals 606 dp, which is just over Android’s 600 dp tablet breakpoint. The two-column episode page of the Hongguo short-drama app and the split-pane settings pages only appear in this layout. Turning it off returns to the phone layout (larger text, less information). The change takes effect the next time you open an app.
This is the physical panel orientation the runtime is using right now, set automatically by the policy above. Only in “Force” mode is it entirely up to you.
The native window is rendered and laid out directly by the emulator, so dragging, resizing and rotating feel responsive, with no black bars or misplaced clicks. The cost is one extra taskbar icon (for landscape use the tray menu or Ctrl+Alt+R). Embedded mode puts the emulator window inside our window, which looks more consistent and has its own rotate button, but it can drop frames and show black bars when resizing, rotating or switching apps. Changes take effect the next time you open an app.
In window mode you can drag the border to resize freely; this sets the internal Android rendering size, and a smaller size saves more performance.
Mouse buttons
The emulator treats the left button as a finger tap, and holding and dragging is a swipe, so no extra setup is needed.
By default the emulator also treats the right button as a tap (easy to trigger by accident). When on, the right button only goes back and no longer taps.
Smooth mode merges the scrolling in a short time span into one swipe gesture, which avoids notch-by-notch jerking and does not start an adb process for every notch.
Side-button mapping needs a global mouse hook. The hook is installed only while an ApkStart West app window is in the foreground and is removed as soon as it loses focus or closes, so it does not slow down the desktop.
The mappings above only apply while an app window is in the foreground; after you switch back to the desktop or close the window, the mouse behaves exactly as Windows normally does.
Key mapping (gamepad)
Maps keyboard keys to Android touch taps and swipes. Good for playing mobile games with a keyboard (WASD to move, J/K for skills, and so on). Each app can be set up on its own: right-click the app card → “Key mapping” and choose a preset template or customize it.
No key mapping is set for the current app. Right-click an app card to apply a preset template quickly.
Performance and resource use
Decides how much CPU the Android virtual machine uses and how sharp the picture is. If video apps such as Hongguo or Douyin stutter, switch to “Smooth”; if you only want to keep small apps running in the background, switch to “Save resources”. Takes effect the next time you open an app.
When a PC has both a dedicated and an integrated graphics card, Windows sometimes assigns the emulator to the integrated one, which makes the picture stutter. Here you can choose which card renders it. Works only on Windows 10 1803 or later; changes apply the next time Android starts.
Growing is done in place: installed apps and saves are kept, but the next app launch takes about ten seconds longer.

Opening an app a second time takes only a few seconds. The cost is an extra file of about 2–3 GB on disk, called ram.bin. If disk space is tight you can turn it off: it only affects startup speed, not your apps or saves.
Container details (advanced)
Limits the vCPU quota and lowers the process priority so the CPU goes to the Windows desktop first. The “Resource policy” above already sets this automatically.
Game mode keeps the Android virtual machine at a higher CPU priority and reduces host-side polling for the lowest input and picture latency; the cost is that other programs on the PC slow down. With no app window open, the container still lowers its priority and parks itself automatically.
Also disables background packages such as the Play Store, the setup wizard and print services, keeping only what is needed to open apps. If an app says Google Play services are missing, turning this switch off restores them automatically.
As soon as ApkStart West starts, it boots the Android environment in the background (the window stays hidden, so you never see the emulator). After that, opening any app is just one “open” step; in testing the wait dropped from 20-plus seconds to almost nothing. The cost is about 1 GB of memory held while idle; with it off, the first app launch needs a cold start.
The Android environment boots only once and stays resident; opening an app afterwards does not re-run the whole system, it only starts that app and stops other app processes. Closing the last window clears the background and parks the container, and the next launch is still instant.

PC check-up · automatic setup
First checks this PC: whether CPU virtualization is on, whether the Windows Hypervisor Platform is present, which graphics card it has and how much video memory, and whether memory and the Windows version are enough. Whatever can be changed automatically (memory / cores / picture quality / rendering backend) is written straight into the settings and saved as a driver; anything that needs administrator rights gets a button; anything that can only be changed in the BIOS tells you how.
Drivers · compatibility patches
Some machines need changed startup parameters to run (an old graphics card with a low GLES version, hardware acceleration turned off, or a driver version that crashes as soon as hardware rendering is on). A driver is just a JSON file that declares “which machines it matches” + “which startup parameters to change when it matches”. You can write, import and share them yourself. A driver only changes startup options on an allow-list and does not run any code; if a machine does not match, the driver has no effect.
Reading drivers…
“Export template for this PC” fills in the matching conditions for this machine. Edit the effect values such as gpuMode / forceTcg, and the driver is ready to use. Field descriptions are in the repository file docs/drivers.md.
Automatic checks · smart diagnostics
Checks this PC regularly in the background: whether the Android runtime is up, whether adb authorization is normal, how much disk space is left, whether the data partition is blocked by the differencing disk, whether the snapshot is damaged, and whether settings conflict with each other. You get a notification only when a new serious problem is found, and only once; everything else is listed quietly below.
When off, scheduled scans stop; you can click “Check now” at any time to run one by hand.
Only serious problems trigger a notification; known old problems do not bother you again.

Runtime
ApkStart West only runs its own runtime: adb, the emulator and the system image are all downloaded and managed by it. It does not detect, take over or depend on any emulator installed on your PC (MuMu, LDPlayer, BlueStacks and WSA are never used). That way, changing PCs, whether someone else has an emulator installed, or how an emulator is upgraded makes no difference here.
Assigned by ApkStart West itself (emulator-5554, moving to the next port automatically if there is a conflict); nothing to fill in.
There is now a single universal Android 14 image that runs both x86 and ARM apps; it is downloaded automatically the first time an ARM app is met, so no manual switching is needed. This switch is only kept for compatibility with old settings.

ApkStart West

A Windows launcher for Android apps that installs with a double-click: APK install, desktop shortcuts, running in separate windows, and two-way file sharing.

The features here are still experimental and may change between versions. If you run into problems, report them from “Diagnostics and repair → Export diagnostic report”.
When on, opening a new app no longer force-closes the previous one: several apps can stay resident and you can switch back to them quickly at any time (sign-in state is kept, with no reload), which feels close to multiple windows. Because the Android runtime has only one emulator window, only one app picture is shown in the foreground at a time, so it is not true side-by-side multi-window. It clearly increases memory use; when off, it returns to the stable “one app shown at a time” mode.
In multi-app mode, background apps beyond this number are suspended (data is kept, and switching back is instant) to free memory.
